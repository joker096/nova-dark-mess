# Инструкция для ИИ-агента: исправление UI/UX мессенджера (светлая тема, кнопки, интерфейсные ошибки)

> Стек: React + TypeScript. Две темы (светлая / тёмная), ~30 экранов (онбординг, логин, OTP, профиль, PIN, чаты, звонки и т.д.).
> Главная проблема: **в светлой теме белый текст на светлом фоне** (нечитаемо). Плюс разные ошибки с кнопками и интерфейсом.

Работай строго по порядку фаз. После каждой фазы коротко отчитывайся: что нашёл, что исправил, какие файлы изменил. Ничего не «переписывай с нуля», пока не проведён аудит (Фаза 0).

---

## 0. Правила работы

1. **Сначала аудит, потом правки.** Не угадывай причины: найди их в коде командами из Фазы 1.
2. **Никаких «точечных заплаток» цветом.** Нельзя лечить белый текст добавлением `color: #000` в одном месте. Причина системная — чиним систему токенов, а не симптомы.
3. **Ни одного захардкоженного цвета в компонентах.** Все цвета только через семантические токены (CSS-переменные). Исключения: цвет бренд-логотипа, цвета эмодзи/иллюстраций.
4. **Обе темы должны работать всегда.** Любое изменение проверяется в светлой и тёмной теме.
5. **Не ломай существующую логику** (стейт, роутинг, API). Меняется только слой представления, плюс явные баги обработчиков.
6. Если в проекте уже есть акцентный цвет/шрифты из UI-кита — **сохрани их**, но проверь контраст (см. §3.3). Если акцент не проходит контраст — затемни его для светлой темы.
7. Все пользовательские тексты оставляй на русском/как в проекте, не меняй копирайт без необходимости.

## 2. Фаза 2 — Единая система тем

### 2.1. Механизм переключения (сделать надёжно)

1. Тема хранится в состоянии `themeMode: 'system' | 'light' | 'dark'` (по умолчанию `'system'`), сохраняется в `localStorage`.
2. «Эффективная» тема (`light`/`dark`) вычисляется: если `system` — по `matchMedia('(prefers-color-scheme: dark)')`, с подпиской на изменение.
3. Тема ставится **на `<html>`**: `document.documentElement.dataset.theme = 'light' | 'dark'` и `document.documentElement.style.colorScheme = 'light' | 'dark'`.
4. **Антивспышка**: в `index.html` в `<head>` ДО загрузки бандла — маленький inline-скрипт, который читает `localStorage` и сразу ставит `data-theme`, чтобы не мигала не та тема:

```html
<script>
  (function () {
    try {
      var mode = localStorage.getItem('themeMode') || 'system';
      var dark = mode === 'dark' || (mode === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
      var t = dark ? 'dark' : 'light';
      document.documentElement.dataset.theme = t;
      document.documentElement.style.colorScheme = t;
    } catch (e) {}
  })();
</script>
```

5. Обновлять `<meta name="theme-color">` при смене темы (цвет = `--bg-app` активной темы), чтобы адресная строка/статус-бар на мобильных не выбивались.
6. Порталы (модалки, тосты, bottom sheet, контекстные меню) рендерить так, чтобы они подчинялись `html[data-theme]`, а не локальному классу.
7. Добавить `transition: background-color .2s, color .2s, border-color .2s` на `body` и основные поверхности (но **не** на всё через `*`, чтобы не лагало), и отключить при `prefers-reduced-motion`.

| Было | Стало |
|------|-------|

| серый текст | `var(--text-secondary)` / `var(--text-tertiary)` |
| фон карточки/хедера | `var(--bg-surface)` |

## 3. Фаза 3 — Светлая тема: детальные требования

### 3.1. Принципы светлой темы
- Страница светло-серая (`--bg-app`), карточки/списки/хедеры белые (`--bg-surface`) — так появляется глубина без тяжёлых теней.
- Разделители — тонкие 1px `--border`, не чёрные.
- Тени мягкие (`--shadow-1`), только у плавающих элементов (FAB, bottom sheet, меню).
- Статусные цвета (ошибка/успех) не должны быть неоновыми — использовать токены из §2.2.
- Фото/обои чата: если используется фон-узор, он должен иметь низкую насыщенность в светлой теме, а пузыри — свои непрозрачные фоны, чтобы текст не терялся на обоях.

### 3.2. Что проверить на каждом экране светлой темы
- Нет ни одного текста светлее `--text-tertiary` (кроме disabled и текста на заливках).
- Иконки в хедере и таб-баре видны (`--text-secondary` неактивные, `--accent` активные).
- Плейсхолдеры читаемы (`--text-tertiary`).
- Фоны инпутов отличаются от фона страницы или имеют рамку (поле не «растворяется»).
- Аватарки-инициалы: фон аватарки достаточно насыщенный, чтобы белые буквы имели контраст ≥ 4.5:1 (например, палитра из 8 тёмных оттенков: `#C2410C #B45309 #15803D #0F766E #1A73D9 #6D28D9 #BE185D #475569`), либо тёмные буквы на пастельном фоне.
- Статус-бар/`theme-color` совпадает с шапкой.

### 3.3. Таблица проверенных контрастов (WCAG 2.1 AA, нужно ≥ 4.5:1 для текста, ≥ 3:1 для крупного текста и иконок)

| Пара | Светлая | Тёмная |
|------|---------|--------|
| основной текст на поверхности | 17.7 : 1 | 14.9 : 1 |
| вторичный текст на поверхности | 7.6 : 1 | 7.9 : 1 |
| третичный текст (время, подписи) на поверхности | 5.0 : 1 (на `--bg-app` 4.55) | 5.5 : 1 |
| белый текст на `--accent` (кнопка) | 4.67 : 1 | 4.67 : 1 |
| ссылка/акцентный текст на поверхности | 4.67 : 1 | 7.05 : 1 |
| исходящий пузырь | 12.4 : 1 | 8.1 : 1 |
| входящий пузырь | 17.7 : 1 | 13.0 : 1 |
| текст ошибки на поверхности | 5.6 : 1 | 6.4 : 1 |

Если меняешь любой цвет — пересчитай контраст (скрипт в §9.2) и не опускайся ниже порогов. `--text-disabled` под порог WCAG не подпадает (отключённые элементы), но всё равно должен быть различим.

## 4. Фаза 4 — Кнопки и интерактивность (исправление багов)

### 4.1. Единый компонент `Button`

Все кнопки приложения должны быть одним компонентом (или тонкими обёртками над ним). Варианты и состояния:

| Вариант | Фон | Текст | Использование |
|---------|-----|-------|---------------|
| `primary` | `--accent` | `--text-on-accent` | главное действие на экране (одно на экран) |
| `secondary` | `--accent-soft` | `--accent`* | второстепенное |
| `outline` | прозрачный, рамка `--border-strong` | `--text-primary` | нейтральное |
| `ghost` | прозрачный | `--accent` | ссылки-кнопки, «Пропустить» |
| `danger` | `--danger` | `--text-on-accent` | удаление, выход |
| `icon` | прозрачный, круг 44×44 | `currentColor` | иконки в хедерах |

\* для `secondary` в светлой теме текст — `--accent` на `--accent-soft`; проверь ≥ 4.5:1, иначе используй `--accent-pressed`.

Обязательные состояния для **каждого** варианта: `default`, `hover` (только `@media (hover: hover)`), `active/pressed` (`scale(.98)` + затемнение), `focus-visible` (кольцо `--focus-ring`), `disabled` (`opacity` + `cursor: not-allowed` + `pointer-events: none`, атрибут `disabled` и `aria-disabled`), `loading` (спиннер, ширина кнопки не прыгает, повторный клик блокируется).

Размеры: `lg` 52px (онбординг, логин), `md` 44px (по умолчанию), `sm` 36px (только на десктопе; на мобильном зона нажатия расширяется до 44px через `::after`/padding). Радиус — `--radius-md`. Минимальная ширина текстовой кнопки 88px.

### 4.2. Чек-лист типовых багов кнопок — найти и исправить

1. **`<div onClick>` вместо `<button>`** → заменить на `<button type="button">`. Иначе нет фокуса с клавиатуры, нет `Enter/Space`, нет `disabled`, неверная семантика для скринридеров. Если элемент — переход, использовать `<a>`/`<Link>`.
2. **Кнопки внутри `<form>` без `type`** → по умолчанию `submit`, из-за чего «Назад», «Показать пароль», «Выбрать страну» отправляют форму/перезагружают страницу. Всем не-submit кнопкам — `type="button"`.
3. **Вложенные интерактивные элементы** (кнопка внутри кнопки, `<button>` внутри `<a>`, переключатель внутри кликабельной строки списка). Исправить структуру; для вложенных действий — `e.stopPropagation()` и отдельная зона нажатия.
4. **Невидимые перекрытия**: прозрачный слой (`position:absolute/fixed`, оверлей, закрытая модалка с `opacity:0`) перехватывает клики. Закрытые модалки/шиты — не в DOM либо `visibility:hidden; pointer-events:none`. Проверить `z-index` по токенам (`--z-*`), убрать «магические» значения 9999.
5. **Зона нажатия < 44×44px** (иконки в хедере, галочки, «закрыть», кнопки в цифровой клавиатуре PIN). Увеличить зону без увеличения иконки.
6. **Двойной сабмит**: при нажатии «Войти / Отправить код / Отправить сообщение» кнопка не блокируется до ответа. Добавить `loading` + `disabled`, защиту в обработчике (`if (isSubmitting) return`).
7. **Disabled выглядит как активная** или наоборот: кнопка визуально активна, но не работает (условие `disabled` не совпадает с валидацией). Привести в соответствие: «Далее» активна только при валидном вводе (телефон корректной длины, OTP 6/4 цифры, PIN введён полностью).
8. **Нет визуальной реакции на нажатие** → добавить `:active` и короткую анимацию (`--transition-fast`).
9. **Hover «залипает» на тач-устройствах** → стили hover только внутри `@media (hover: hover) and (pointer: fine)`.
10. **Синий хайлайт/выделение текста при тапе** → `-webkit-tap-highlight-color: transparent; user-select: none` на кнопках и элементах списка (но не на тексте сообщений!).
11. **Двойной тап-зум и задержка 300 мс** → `touch-action: manipulation` на интерактивных элементах; `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.
12. **Кнопка не реагирует на клавиатуру**: Enter в поле ввода сообщения должен отправлять (Shift+Enter — перенос), Enter в логине/OTP — сабмит, Esc закрывает модалки и шиты.
13. **Потеря фокуса/нет возврата фокуса** после закрытия модалки → вернуть фокус на вызвавший элемент; внутри модалки — focus trap.
14. **Обработчики на неверном элементе** (`onClick` на обёртке, а клик по иконке внутри не срабатывает из-за `pointer-events: none` у дочернего элемента или наоборот). Проверить каждую иконку-кнопку.
15. **Утечки/дублирование обработчиков** (`addEventListener` в `useEffect` без cleanup → кнопка срабатывает 2–3 раза). Проверить все `useEffect` с подписками.
16. **Нет `aria-label` у иконок-кнопок** (назад, поиск, звонок, видео, меню, прикрепить, отправить, микрофон, закрыть) → добавить подписи на русском.
17. **Тексты на кнопках переносятся/обрезаются** в узких экранах и при длинных переводах → `white-space: nowrap` для коротких, `min-height` + `padding` вместо фиксированной высоты для многострочных.
18. **Поле «Отправить» ↔ «Микрофон»**: в поле сообщения при пустом тексте показывать микрофон/вложения, при наличии текста — «Отправить». Переход анимированный, без сдвига поля ввода.

### 4.3. Специфические компоненты

**OTP-ввод:**
- `inputMode="numeric"`, `autocomplete="one-time-code"`, `pattern="[0-9]*"`;
- авто-переход между ячейками, `Backspace` возвращает назад, поддержка вставки целого кода из буфера;
- активная ячейка подсвечена рамкой `--accent`; ошибка — рамка `--danger` + тряска (отключается при reduced-motion) + сообщение под полем;
- кнопка «Отправить код повторно» неактивна с таймером (`00:42`), затем становится `ghost`.

**PIN-клавиатура:**
- кнопки цифр 72×72 (минимум 64), `:active` с заметной подсветкой, без задержки;
- индикаторы точек: пустая — `--border-strong`, заполненная — `--text-primary`; ошибка — тряска + вибрация (`navigator.vibrate`) + сброс;
- «Стереть» и «Биометрия» — иконки с `aria-label`;
- цифры используют `--text-primary` (в светлой теме не белые!).

**Поле ввода сообщения:**
- автоувеличение до 5–6 строк, затем внутренний скролл;
- кнопки вложений/эмодзи/отправки выровнены по нижней линии поля;
- не прыгает при открытии мобильной клавиатуры (использовать `100dvh`, `visualViewport`, `env(safe-area-inset-bottom)`).

**Переключатели (Switch):** размер 51×31, дорожка выкл. — `--border-strong`, вкл. — `--accent`, бегунок белый с тенью; активна вся строка; `role="switch"` + `aria-checked`.

**Модалки/Bottom sheet/меню:** подложка `--bg-overlay`, закрытие по тапу вне, `Esc`, свайпу вниз (шит), блокировка скролла фона, анимация появления 200 мс.

### 9.2. Проверка контраста токенов (запускать в CI при изменении `tokens.css`)

Небольшой скрипт: считает контраст пар «текст ↔ фон» по таблице ниже и падает, если ниже порога.

```ts
// scripts/check-contrast.ts
const lum = (hex: string) => {
  const [r, g, b] = [1, 3, 5].map(i => parseInt(hex.slice(i, i + 2), 16) / 255)
    .map(c => (c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4));
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
};
const ratio = (a: string, b: string) => {
  const [x, y] = [lum(a), lum(b)].sort((p, q) => q - p);
  return (x + 0.05) / (y + 0.05);
};
// пары: [название, текст, фон, минимум]
const pairs: [string, string, string, number][] = [
  ['light text/surface', '#111827', '#FFFFFF', 4.5],
  ['light text2/app',    '#4B5563', '#F3F5F8', 4.5],
  ['light text3/surface','#667085', '#FFFFFF', 4.5],
  ['light on-accent',    '#FFFFFF', '#1A73D9', 4.5],
  ['light out bubble',   '#0B2447', '#D6E8FF', 4.5],
  ['dark text/surface',  '#F2F5F8', '#17212B', 4.5],
  ['dark text3/surface', '#8A97A6', '#17212B', 4.5],
  ['dark out bubble',    '#FFFFFF', '#2B5278', 4.5],
];
let failed = false;
for (const [n, fg, bg, min] of pairs) {
  const r = ratio(fg, bg);
  if (r < min) { failed = true; console.error(`FAIL ${n}: ${r.toFixed(2)} < ${min}`); }
}
process.exit(failed ? 1 : 0);
```
