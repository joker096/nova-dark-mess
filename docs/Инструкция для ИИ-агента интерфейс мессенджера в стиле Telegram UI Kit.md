# Инструкция для ИИ-агента: интерфейс мессенджера в стиле Telegram UI Kit

Этот документ — готовое ТЗ. Скопируйте его целиком в чат с ИИ-агентом, который работает с кодом приложения-мессенджера (React + TypeScript). Все значения ниже сняты с макета Figma; то, что оценено «на глаз» по скриншотам, помечено **(сверить)**.

## 1. Цель

Переделать интерфейс существующего мессенджера так, чтобы он визуально и по поведению повторял Telegram UI Kit (Community): светлая и тёмная темы, голубой акцент, плоская лента сообщений без «пузырей», карточные списки настроек, плавающая нижняя панель вкладок, модальные листы. **Бизнес-логику, API, шифрование и роутинг не менять** — только слой представления.

## 3. Порядок работы агента

1. **Аудит проекта.** Прочитайте `package.json`, структуру `src/`, текущую систему стилей (CSS Modules / Tailwind / styled-components / др.), роутинг, список существующих экранов и компонентов. Составьте для себя таблицу «экран макета → экран приложения». Не предполагайте стек — определите его.
2. **Токены.** Заведите единый слой дизайн-токенов (раздел 4) и переключатель тем. Ничего не хардкодьте в компонентах.
3. **Базовые компоненты** (раздел 6) — по одному, сразу в обеих темах.
4. **Экраны** (раздел 7) — в порядке: чат-лента → список чатов → настройки/профиль → контакты → поиск → листы и меню.
5. **Проверка.** После каждого экрана сравнивайте с `get_screenshot` макета на 390 px в светлой и тёмной теме. Запускайте `tsc --noEmit`, линтер и существующие тесты.
6. Делайте небольшие коммиты по компонентам, не одним огромным.

Перед началом коротко сообщите пользователю, какой стек обнаружили и какой план составили. Если требуется решение (например, оставить ли вкладку «Node», см. раздел 9), — спросите, не угадывайте.

## 4. Дизайн-токены

Ниже значения, которые Figma отдала как переменные (`get_variable_defs`). Названия токенов в макете — `primary-base`, `text/strong-950` и т. д.; в коде используйте CSS-переменные.

```css
:root {
  /* бренд */
  --color-primary: #0087fd;        /* primary-base, ссылки, активная вкладка, кнопки */
  --color-accent: #008bff;         /* Accent: иконки, "Back", действия в шапке */
  --color-info: #339ffd;           /* state/information/base: пузырь пользователя в ИИ-чате, бейджи */
  --color-info-dark: #000e19;

  /* текст */
  --text-strong: #171717;          /* text/strong-950 */
  --text-soft: #a3a3a3;            /* text/soft-400: время, подписи, плейсхолдеры */
  --text-control-primary: #404040; /* Labels - Controls/Primary */
  --text-control-secondary: #8c8c8c;

  /* поверхности */
  --bg-white: #ffffff;             /* карточки, списки */
  --bg-weak: #f7f7f7;              /* bg/weak-25: поле поиска, блоки ссылок (светло-серо-голубой оттенок, сверить) */
  --bg-soft: #ebebeb;              /* bg/soft-200: кнопки «Invite», чипы */
  --bg-screen: #ededf0;            /* общий серый фон экранов с карточками (сверить пипеткой) */
  --stroke-soft: #ebebeb;          /* stroke/soft-200: разделители */
  --static-black: #171717;
}

[data-theme="dark"] {
  --color-primary: #339ffd;        /* в тёмной теме акцент светлее */
  --color-info: #0087fd;
  --color-info-dark: #339ffd;

  --text-strong: #ffffff;
  --text-soft: #7b7b7b;

  --bg-weak: #1c1c1c;              /* bg/weak-25 */
  --bg-soft: #333333;              /* bg/soft-200 */
  --stroke-soft: #5c5c5c;          /* stroke/sub-300 */
  --bg-screen: #171717;            /* фон ленты чата (по скриншоту, сверить) */
  --bg-white: #1c1c1c;             /* карточки в тёмной теме (сверить на экранах настроек) */
}
```

Переключение темы: атрибут `data-theme` на `<html>`, по умолчанию — `prefers-color-scheme`, ручной выбор хранится в локальном хранилище. Цвета имён отправителей в группах — палитра из нескольких оттенков (в макете виден фиолетовый `#9b6bd1`-подобный, **сверить**); назначайте цвет детерминированно по id пользователя.

Цветные иконки пунктов настроек (скруглённые квадраты 28 px): синий, зелёный (звонки), оранжевый (устройства), бирюзовый (папки) — берите из макета пипеткой.

### Геометрия (оценка по скриншотам, **сверить**)

- Отступы экрана по горизонтали: 16 px. Карточки: фон `--bg-white`, радиус ≈ 24, внутри строки высотой 48–56 с разделителем, начинающимся после иконки (inset ≈ 60 px).
- Поле поиска и поле ввода: полностью скруглённая «таблетка», высота 36–40.
- Аватары: 40 px в ленте и списках, 100 px в профиле, 36 px в столбце рабочих пространств; всегда круглые.
- Круглые кнопки (вложение, микрофон, отправка): 36–40 px.
- Фото и видео в сообщениях: радиус ≈ 8; блок ссылки: радиус ≈ 8, левая полоса 3 px акцентного цвета.
- Лист (bottom sheet): верхние углы ≈ 24, «ручка» 36×5 по центру сверху.
- Тени почти не используются; глубина создаётся контрастом фона и белых карточек. Нижняя панель вкладок — единственный «плавающий» элемент с лёгкой тенью/размытием.

## 5. Общие принципы

- **Mobile first, 390 px.** Макет мобильный. На десктопе — центральная колонка до 480 px с серым фоном по бокам, либо двухпанельный режим (список чатов слева + чат справа) на ширине от 900 px.
- **Safe areas:** `env(safe-area-inset-*)` сверху (статус-бар ≈ 45 px) и снизу (индикатор «Home»).
- **Темы:** любой компонент обязан выглядеть правильно в обеих темах; сразу проверяйте обе.
- **Доступность:** контраст текста не ниже WCAG AA, видимый фокус для клавиатуры, `aria-label` на иконках-кнопках, минимальная зона нажатия 44×44.
- **Иконки:** в макете используется собственный шрифт `tgicon`. Не копируйте его. Используйте существующий набор иконок проекта либо SVG-набор с лицензией, допускающей коммерческое использование (например Lucide / Phosphor), единый размер 24–28 px, цвет `currentColor`.
- **Анимации:** переходы между экранами — сдвиг 250–300 мс, листы — снизу вверх, появление сообщений — лёгкий fade; уважайте `prefers-reduced-motion`.

## 6. Каталог компонентов

Создайте каждый как отдельный типизированный компонент с пропсами и сторибуком/страницей-демо (если в проекте есть Storybook).

1. **NavBar** — высота 44 под статус-баром. Слева «Back» (шеврон + текст, цвет `--color-accent`) либо «Cancel»; по центру заголовок (Body/Semibold, для групп с иконкой «#» перед названием); справа действие текстом («Edit», «Save») или иконкой. Под панелью тонкий разделитель.
2. **TabBar (плавающая)** — таблетка с отступом от краёв и от низа, пять вкладок: Contacts, Calls, Chats, Node, Settings (иконка 27 px + подпись 12 px). Активная вкладка — акцентный цвет, подсвечена скруглённой плашкой-фоном. Бейдж непрочитанных — на иконке Chats. Адаптируйте набор вкладок под свои разделы.
3. **Avatar** — круг, размеры 24/36/40/100, фоллбэк на инициалы с цветом по id, индикатор онлайна (зелёная точка с белой обводкой) на аватаре в шапке профиля.
4. **Badge** — пилюля со счётчиком: акцентная (обычная) и серая (для заглушённых чатов); формат «999+».
5. **Card / ListGroup / ListRow** — белая карточка с радиусом, строки: цветная иконка-квадрат 28 px слева, заголовок Label/Medium, справа шеврон или значение; разделитель с отступом.
6. **SearchField** — таблетка с лупой, плейсхолдер `--text-soft`; в режиме ввода слева «Cancel».
7. **Message (плоская, без пузырей)** — аватар 40 слева; в первой строке имя (цветное, Label/Small) и время (серое, 12 px); ниже текст; под текстом блок реакций и строка «N replies» со стопкой мини-аватаров. Сообщения одного автора подряд группируются без повтора аватара. Варианты (см. node `190:2627`):
   - текст;
   - ссылка: превью-карточка с левой полосой, название сайта акцентным, заголовок жирным, описание, картинка;
   - изображение (скруглённое, на всю ширину контента);
   - видео: изображение + круглая кнопка Play по центру;
   - файл: круглая акцентная кнопка загрузки, имя файла акцентным цветом, размер серым;
   - ответ: над текстом строка «Replied in a chat» и цитата акцентным цветом, обрезанная до одной строки;
   - пересылка: блок с оранжевой левой полосой, «Forwarded from <автор>», текст оригинала.
8. **ReactionChips** — пилюли «эмодзи + число», выбранная пользователем — с акцентной обводкой; чип со стопкой аватаров для реакций нескольких людей.
9. **DateSeparator** — по центру серая пилюля с датой («13th December»), прилипает к верху при прокрутке.
10. **Composer (поле ввода)** — слева круглая кнопка вложений, по центру таблетка с полем «Message» и смайлом внутри справа, справа круглая кнопка микрофона; при наличии текста микрофон заменяется кнопкой отправки; режим ответа/редактирования — полоса над полем с отменой. Поле растёт по высоте до 5 строк.
11. **BottomSheet** — ручка, шапка «Cancel — заголовок — Save», содержимое; закрывается свайпом, тапом по затемнению и Esc.
12. **ActionTile** — квадрат 38 px с иконкой и подписью 12 px под ним (ряд «Share invite / Copy link / QR code / …»).
13. **PillButton** — «Invite» (серая `--bg-soft`) ↔ «Invited» (светло-голубая, акцентный текст).
14. **AlphabetIndex** — вертикальная полоса букв A–Z и «#» у правого края списка контактов, акцентный цвет, быстрый скролл к секции по касанию/перетаскиванию; заголовки секций с буквой на серой подложке.
15. **ContextMenu** — меню над сообщением (Reply, Forward, Edit, Copy, Delete) по долгому нажатию/ПКМ; закрывается по тапу вне меню.
16. **Segmented tabs (подчёркивание)** — две-три вкладки сверху, активная акцентным цветом с подчёркиванием 3 px.
17. **AI bubble (чат с ассистентом)** — сообщение пользователя: акцентная пилюля справа с тёмным текстом; ответ ассистента — простой текст на фоне без пузыря; индикатор «Searching conversations and files…» серым; кнопка «стоп» (квадрат) в круглой акцентной кнопке на месте отправки. Реализуйте, только если в приложении есть ИИ-функции.

## 7. Экраны

**Групповой чат.** NavBar с «Back» и названием группы (иконка «#» слева от названия). Лента на всю высоту: разделители дат, группы сообщений всех вариантов из раздела 6, виртуализированный список (react-virtuoso или аналог), автоскролл вниз только если пользователь уже внизу, кнопка «вниз» со счётчиком новых. Внизу Composer, при открытой клавиатуре — поднимается вместе с ней.

**Список чатов.** Шапка: аватар пользователя с индикатором онлайна, имя и @username, ниже поле поиска. Если в продукте есть рабочие пространства, слева вертикальный столбец аватаров 36 px с бейджами (активное — с синей вертикальной отметкой слева, ниже кнопка «+»); справа основная панель с белыми скруглёнными краями и сворачиваемыми секциями: «Summary» (кнопка-пилюля «Summarize the day»), «Voice» (живые голосовые комнаты карточками-чипами с горизонтальной прокруткой), «Chats» (список каналов `# Название @канал` с бейджами). Если рабочих пространств нет — упростите до обычного списка: аватар, название, последнее сообщение, время, бейдж.

**Настройки / профиль.** Серый фон. Вверху аватар 100 px, имя крупно, телефон и @username серым, справа «Edit», слева иконка QR. Далее отдельные карточки: «Change Profile Photo» (акцентный текст), «My Profile», «Wallet» (опционально), группа «Saved Messages / Recent Calls / Devices / Chat Folders».

**Мой профиль.** NavBar «Back — My Profile — Edit», сегментированные вкладки, градиентная обложка (от белого к светло-голубому), аватар с кнопкой-карандашом, карточка полей «name» и «about me».

**Информация о группе.** Крупная иконка/аватар по центру, название, две широкие кнопки-карточки «Mute» и «Search», карточка «Share link» со ссылкой акцентным цветом и значком QR, пояснение серым 12 px.

**Контакты.** Поле «Contact or username», секции по буквам, строка: аватар, имя, статус («online» акцентным, «last seen …» серым), справа AlphabetIndex.

**Лист «Пригласить».** BottomSheet: ряд ActionTile, поле поиска, строка «ссылка действует 7 дней. Edit invite link ›», белая карточка со списком людей и кнопками PillButton.

**Поиск.** Четыре состояния из макета: пустой ввод (история и подсказки), ввод (живые результаты), результаты по сообщениям (карточки с подсветкой совпадений), результаты по вкладкам (чаты / медиа / ссылки / файлы).

**Ответ и пересылка.** Над Composer — полоса с цитатой и кнопкой закрытия; пересылка — экран выбора получателей с поиском и чекбоксами, внизу кнопка подтверждения.

**Звонки, медиа-галерея, остальное.** Реализуйте по соответствующим экранам макета, используя те же компоненты; сначала экраны, у которых в приложении уже есть логика.

## 8. Состояния, которые нужно покрыть

- загрузка (скелетоны вместо спиннеров в списках), пустое состояние, ошибка с кнопкой «Повторить»;
- отправка сообщения: отправляется → отправлено → прочитано (иконки галочек), ошибка с повторной отправкой;
- нет сети: баннер сверху, очередь отправки;
- длинные слова и ссылки не ломают вёрстку (`overflow-wrap: anywhere`);
- RTL-языки, если приложение их поддерживает (используйте логические свойства `margin-inline-*`).

## 9. Что решить с пользователем до начала

1. Нужна ли вкладка «Node» (столбец рабочих пространств с голосовыми комнатами и сводкой дня ИИ)? В макете это особенность конкретного приложения, а не стандартный Telegram. По умолчанию — **не делать**, список чатов оставить обычным.
2. Нужен ли кошелёк («Wallet»), ИИ-ассистент и сводка дня? Делать, только если эти функции есть в продукте.
3. Нужен ли отдельный вид Android или достаточно одного адаптивного интерфейса? По умолчанию — один интерфейс по iOS-макету.

## 10. Чего нельзя делать

- Не копировать из файла макета фотографии, аватары, логотипы и бренды (Warux, Mainnet и др.) — это демо-контент. Используйте плейсхолдеры или свои ресурсы.
- Не использовать название и логотип Telegram в интерфейсе, на экранах и в тексте приложения: нужен собственный бренд. Стиль повторяем, товарный знак — нет.
- Не ломать существующую логику, API и типы; не переписывать роутинг без необходимости.
- Не добавлять новые тяжёлые зависимости без согласования; сначала используйте то, что уже есть в проекте.
- Не хардкодить цвета и размеры — только токены.
- Не оставлять заглушки вида `TODO` без отметки в итоговом отчёте.

## 11. Критерии приёмки

### Правила для агента

1. Создайте один файл темы (например `src/theme/tokens.css` или `theme.ts`), где объявлены **все** роли из таблиц выше для светлой и тёмной тем. Если колонка «Ваше значение» заполнена — берите её, иначе значение макета.
2. В компонентах используйте только `var(--…)`. Hex, `rgb()` и числа вроде `24px` для радиусов и отступов вне файла темы запрещены.
3. Если для экрана нужна роль, которой нет в таблице, не придумывайте цвет: добавьте новую роль в файл темы, дайте ей значение из макета и перечислите такие роли в итоговом отчёте.
4. Переименование роли допустимо только если в проекте уже есть своя схема именования; тогда сделайте таблицу соответствий в комментарии к файлу темы.
5. Каждый экран должен корректно выглядеть в обеих темах без правок самого экрана: меняется только файл темы.
