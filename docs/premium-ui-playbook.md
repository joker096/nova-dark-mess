# Как сделать из простого приложения премиальное: скиллы, наработки, план

Дата подборки: 17.11.2026. Все ссылки взяты из результатов поиска. Цифры звёзд и установок на разных сайтах расходятся, поэтому я их почти не привожу. Перед установкой любого скилла откройте его `SKILL.md`: это инструкции, которым будет следовать ваш агент.

---

## 1. Быстрый выбор (если читать только это)

| Задача | Что взять |
|---|---|
| Убрать «шаблонный ИИ-вид», задать направление дизайна | `frontend-design` (Anthropic) |
| Найти и исправить конкретные проблемы в готовом UI | `impeccable` (команды `audit`, `critique`, `polish`) |
| Подобрать стиль, палитру, шрифты, UX-правила под тип продукта | `ui-ux-pro-max` |
| Сделать интерфейс «дорогим»: воздух, глубина, мягкие анимации | `taste-skill` и `soft-skill` / `redesign-skill` |
| Анимации и ощущение «отзывчивости» | `emil-design-eng`, `motion-design-patterns` |
| Проверить доступность и баги интерфейса по чек-листу | `web-design-guidelines` (Vercel) |
| Взять готовую дизайн-систему известного бренда | `awesome-design-md` (DESIGN.md) |
| Готовые компоненты (React) | shadcn/ui + Magic UI / Motion Primitives / Aceternity |

**Рекомендуемая связка:** `impeccable` (аудит) → `taste-skill` / `soft-skill` (визуальный уровень) → `emil-design-eng` (анимации) → `web-design-guidelines` (финальная проверка).

## 2. Скиллы для ИИ-агентов (Claude Code, Codex, Cursor и др.)

### 2.1 frontend-design (Anthropic)
- **Что делает:** задаёт осознанное визуальное направление: типографика, цвет, композиция, движение. Борется с «шаблонным» видом.
- **Ссылка:** https://github.com/anthropics/skills (папка `skills/frontend-design`)
- **Установка:** `npx skills add https://github.com/anthropics/skills --skill frontend-design`
- **Лицензия:** Apache-2.0.
- **Когда брать:** как база для любой новой или переделываемой страницы или экрана.
- **Обзор:** https://www.anavem.com/skills/claude/anthropic-frontend-design-skill

### 2.2 Impeccable (Paul Bakaus)
- **Что делает:** один скилл и около 20 команд. Среди них `teach` (собирает контекст проекта в `PRODUCT.md` и `DESIGN.md`), `shape` (планирование UX до кода), `critique` (разбор иерархии и ясности), `audit` (доступность, производительность, адаптивность), `polish`, `animate`, `distill` и другие. Содержит список анти-паттернов: фиолетовые градиенты, боковые цветные рамки, bounce-анимации, мелкие тач-зоны и т. п.
- **Ссылки:** https://github.com/pbakaus/impeccable, сайт https://impeccable.style
- **Отдельный CLI без ИИ:** `npx impeccable detect src/`. Сканирует код на анти-паттерны.
- **Установка:** `npx impeccable install` или копирование готового бандла из `dist/claude-code/.claude` в проект.
- **Когда брать:** когда приложение уже есть и нужно понять, что именно в нём плохо.
- **Обзор с тестом на реальном сайте:** https://www.mejba.me/blog/impeccable-claude-code-design-skill
- **Нюанс:** полный набор команд занимает заметную часть контекста. Подключайте его для дизайн-сессий, а не для рефакторинга.

### 2.3 UI UX Pro Max (nextlevelbuilder)
- **Что делает:** база знаний с локальным поиском: десятки стилей (glassmorphism, bento, minimalism и др.), палитры по типам продуктов, пары шрифтов, UX-правила, анти-паттерны, рекомендации под стеки (React, Next.js, Vue, SwiftUI, React Native, Flutter, shadcn/ui и др.). Может генерировать дизайн-систему проекта.
- **Ссылка:** https://github.com/nextlevelbuilder/ui-ux-pro-max-skill (лицензия MIT)
- **Установка (Claude Code):**
  - `/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill`
  - `/plugin install ui-ux-pro-max@ui-ux-pro-max-skill`
  - либо `npm install -g ui-ux-pro-max-cli`, затем `uipro init --ai claude`
- **Когда брать:** когда непонятно, какой стиль, палитра и шрифты подходят вашему типу продукта.
- **Обзор:** https://www.anavem.com/skills/claude/ui-ux-pro-max-skill

### 2.4 Taste Skill (Leonxlnx)
- **Что делает:** набор скиллов против «генерик-вида». Основной скилл регулируется тремя ручками (1–10): разнообразие раскладки, интенсивность анимаций, плотность информации.
- **Варианты:**
  - `taste-skill` — универсальный
  - `soft-skill` — «дорогой» мягкий UI: белое пространство, глубина, пружинные анимации
  - `redesign-skill` — для существующих проектов: сначала аудит, затем исправление главных проблем
  - `output-skill` — против обрезанных и недописанных ответов модели
  - `stitch-skill` — правила под Google Stitch с экспортом `DESIGN.md`
  - есть скиллы для генерации макетов-картинок, в том числе мобильных экранов
- **Ссылки:** https://github.com/Leonxlnx/taste-skill, сайт https://tasteskill.dev
- **Установка:** `npx skills add https://github.com/Leonxlnx/taste-skill`, либо отдельный скилл через `--skill "high-end-visual-design"` (это `soft-skill`)
- **Когда брать:** когда нужен именно «премиум-вайб». Для простого приложения хорош `redesign-skill`.
- **Нюанс:** текущая версия основного скилла помечена как v2 (экспериментальная), прежняя доступна как `design-taste-frontend-v1`.

### 2.5 Emil Kowalski: emil-design-eng, review-animations, improve-animations
- **Что делает:** философия «design engineering»: когда анимировать и когда нет, какие easing и длительности, пружины, жесты, `clip-path`, производительность, `prefers-reduced-motion`, чек-лист ревью. `review-animations` строго проверяет анимации по правилам автора, `improve-animations` аудирует всю кодовую базу и выдаёт приоритизированные планы.
- **Ссылки:** https://github.com/emilkowalski/skills, курс автора https://animations.dev
- **Установка:** `npx skills add https://github.com/emilkowalski/skills --skill emil-design-eng`
- **Когда брать:** когда интерфейс «работает, но ощущается вялым».
- **Лицензия:** MIT.

### 2.6 Motion Design Patterns
- **Что делает:** паттерны Framer Motion (Motion) для React: пружины, stagger, layout-анимации, микро-взаимодействия, скролл-эффекты, переходы страниц.
- **Ссылка:** https://agentskills.so/skills/dylanfeltus-skills-motion-design-patterns

### 2.7 web-design-guidelines (Vercel)
- **Что делает:** проверяет UI-код на соответствие Web Interface Guidelines (доступность, производительность, визуальная стабильность, анимации) и выдаёт находки в формате `файл:строка`. Свежие правила подтягиваются при каждом запуске.
- **Ссылки:** https://github.com/vercel-labs/agent-skills, правила: https://github.com/vercel-labs/web-interface-guidelines
- **Установка:** `npx skills add vercel-labs/agent-skills --skill web-design-guidelines`
- **Нюанс:** нужен доступ в сеть, чтобы скачать актуальные правила.
- **Рядом в том же репозитории:** `vercel-react-best-practices`, `vercel-composition-patterns`, `vercel-react-native-skills`, `vercel-react-view-transitions`.

### 2.8 Дизайн-системы в формате DESIGN.md
- **Идея:** положить в корень проекта файл `DESIGN.md` с токенами, типографикой, компонентами и запретами. Агент читает его и строит UI в нужном стиле.
- **awesome-design-md (VoltAgent):** коллекция DESIGN.md, снятых с известных продуктов (Stripe, Linear, Vercel, Notion, Supabase и др.). https://github.com/VoltAgent/awesome-design-md
- **awesome-claude-design:** коллекция DESIGN.md для Claude Design. https://github.com/VoltAgent/awesome-claude-design
- **Каталог:** https://getdesign.md/
- **Использование:**
  1. Скопировать подходящий `DESIGN.md` в корень проекта.
  2. Заменить цвета, шрифты и отступы на свои.
  3. Попросить агента собрать компонент и сравнить с эталоном.
- **Нюанс:** брать чужую систему целиком не стоит. Копирование «в лоб» даёт похожесть на чужой бренд, а не собственное лицо.

### 2.9 Наборы и коллекции
- **UX/UI Agent Skills** (токены, компоненты, WCAG 2.2, дизайн-системы): https://github.com/plugin87/ux-ui-agent-skills
- **Designer Skills Collection** (исследования, дизайн-системы, UX-стратегия, UI, прототипирование): https://vibeindex.ai/collection/owl-listener/designer-skills
- **Большой обзор «20 лучших скиллов для UI/UX»:** https://pasqualepillitteri.it/en/news/576/claude-code-skills-design-uiux-guide
- **Каталоги скиллов:** https://skills.sh, https://playbooks.com/for/ux, https://claudemarketplaces.com/skills/category/design-ui

## 4. Что делать, чтобы превратить простое приложение в премиальное

Это практический план. Он основан на правилах из перечисленных скиллов и общепринятой практике, а не на отдельном исследовании.

### Шаг 0. Зафиксировать «до»
- Сделать скриншоты всех ключевых экранов (светлая и тёмная тема, мобильный и десктоп).
- Запустить `impeccable critique` и `impeccable audit` или `npx impeccable detect src/`. Сохранить список проблем.

### Шаг 1. Создать единый источник правды
- Завести `DESIGN.md` (токены, типографика, компоненты, запреты) и `PRODUCT.md` (кто пользователь, тон, цели).
- Команда `impeccable teach` собирает это из контекста проекта.
- **Все следующие правки идут через токены, а не точечные значения.** Иначе исправления не держатся.

### Шаг 2. Дизайн-токены
- **Цвет:** одна основная палитра (оттенки от светлого до тёмного), нейтральные цвета с лёгким оттенком бренда вместо чистого серого, семантические цвета (успех, ошибка, предупреждение). Тёмная тема проектируется отдельно, а не инверсией.
- **Типографика:** 1–2 шрифта, модульная шкала размеров, ограниченный набор начертаний. Уйти от «Inter по умолчанию на всём».
- **Отступы:** шкала на сетке 4 или 8 px. Никаких произвольных значений.
- **Радиусы, тени, обводки:** 3–4 уровня на всё приложение.

### Шаг 3. Иерархия и воздух
- На экране один главный акцент и одно главное действие.
- Увеличить внутренние отступы и межстрочные интервалы. Нехватка воздуха сильнее всего выдаёт «простоту».
- Сгруппировать связанное (близость), разделять отступами, а не линиями.
- Ограничить число размеров и весов шрифта на экране.

### Шаг 4. Единые компоненты
- Свести кнопки, поля, карточки, списки, модальные окна к одному набору с вариантами (размер, состояние).
- Для каждого интерактивного элемента: default, hover, focus, active, disabled, loading, error.
- Иконки одного семейства и одной толщины.

### Шаг 5. Состояния, которые отличают премиум от «просто красиво»
- Пустые состояния с пояснением и действием.
- Скелетоны вместо спиннеров на длинных загрузках.
- Понятные ошибки: что случилось и что делать.
- Оптимистичные обновления, подтверждение успеха без лишних модальных окон.
- Отмена вместо вопроса «вы уверены?», где это возможно.

### Шаг 6. Движение
- Анимация должна объяснять, а не украшать: показывать причинно-следственную связь, появление и исчезновение, смену контекста.
- Длительности: быстрые отклики 100–200 мс, переходы и панели около 200–400 мс. Не использовать `ease-in` для UI (кажется вялым), брать `ease-out` и пружины для жестов.
- Нажатие: лёгкое сжатие (`scale` около 0.97–0.98).
- Анимировать `transform` и `opacity`, не размеры и позиции через layout.
- Учитывать `prefers-reduced-motion`.
- Инструменты: `emil-design-eng`, `review-animations`, Motion.

### Шаг 7. Адаптивность и тач
- Тач-цели не меньше примерно 44×44 px.
- Проверить на узких экранах, с экранной клавиатурой, в альбомной ориентации.
- Учесть безопасные зоны (чёлки, нижняя панель жестов).

### Шаг 8. Доступность
- Контраст текста по WCAG (4.5:1 для обычного).
- Видимый фокус, полная навигация с клавиатуры.
- Подписи (`aria-label`) у иконок-кнопок, корректные заголовки и роли.
- Прогнать `web-design-guidelines` и исправить находки.

### Шаг 9. Микротексты и тон
- Короткие глаголы на кнопках («Сохранить», а не «ОК»), единая терминология.
- Ошибки без вины пользователя и без технического жаргона.
- Один тон на всё приложение.

### Шаг 10. Производительность как часть премиума
- Нет скачков раскладки (у картинок заданы размеры), шрифты не мигают, взаимодействия отзываются мгновенно.
- Плавность на слабых устройствах важнее эффектов.

### Шаг 11. Финальная проверка
- Повторить аудит и сравнить скриншоты «до» и «после».
- Показать 3–5 реальным людям и спросить, что непонятно, а не что нравится.

## 5. Готовые промпты для агента

**Аудит:**
> Используй скилл impeccable. Выполни critique и audit для экранов в `src/`. Выдай список проблем по приоритету: иерархия, типографика, цвет, состояния, доступность, адаптивность. Код пока не меняй.

**Единая система:**
> Создай `DESIGN.md` из текущего кода: токены цвета, типографики, отступов, радиусов, теней, набор компонентов. Затем перенеси все хардкод-значения в токены.

**Премиум-слой:**
> Используй taste-skill (soft-skill) с низкой интенсивностью анимаций. Улучши экраны X и Y: воздух, иерархия, состояния компонентов. Ничего не ломай в логике.

**Анимации:**
> Используй emil-design-eng. Проведи аудит анимаций, дай приоритизированный план, затем исправь топ-5 проблем. Учти `prefers-reduced-motion`.

**Финальная проверка:**
> Прогони web-design-guidelines по `src/components` и `src/screens`, исправь находки и покажи, что осталось.

## 6. Предостережения

- Скиллы — это текстовые инструкции, а не гарантия качества. Они не заменяют пользовательское тестирование и вкус.
- Не ставьте всё сразу: пересекающиеся скиллы конфликтуют и съедают контекст. Начните с двух-трёх.
- Звёзды и установки показывают популярность, а не качество или безопасность.
- Информация о репозиториях взята из сторонних обзоров и каталогов. Актуальные команды установки сверяйте в README самого репозитория.
- Не копируйте чужую дизайн-систему целиком: берите принципы, а цвета, шрифты и характер делайте своими.
